Server down runbook

homelab-01 at 192.168.20.100. Written 26 October 2026, after the Docker address pool outage. A copy lives in the private GitHub repo homelab-config.

What stops and what keeps working

Stops
  • Every home.arpa service: Plex, Jellyfin, ErsatzTV, books, quiz, status, assets, homepage, maps
  • The server's AdGuard. House devices fall over to the Pi, so lookups feel slow, not broken
  • Vaultwarden. Password apps use their cached copy; the web vault is offline
  • The Cloudflare tunnel and anything public through it
  • Uptime Kuma, Diun, ripping, GitHub runners, nightly backups
  • DNS on the Server_Lab VLAN, which has no fallback
Keeps working
  • Internet and the router
  • The Pi's AdGuard at 192.168.40.100 (admin at port 8053)
  • Home Assistant, Zigbee lights and sensors, Hive heating
  • Home Assistant pings the server and alerts your phone when it is down

There is no UPS yet, so a power cut stops the server abruptly. BIOS AC Recovery is set to Power On, so it restarts by itself when power returns.

First five minutes

From the PC, is the server alive? Replies mean it is up and the problem is a service or the network. No replies means go to the console.

ping -n 3 192.168.20.100

Is the router routing to the server's VLAN? Replies here mean the router side is fine.

ping -n 3 192.168.20.1

On the server console, what is running? Anything that should be up but is missing is the lead.

docker ps --format '{{.Names}}  {{.Status}}'

What has stopped? Two old test containers named sad_williams and tender_panini were removed on the day this was written, so any entry now is new.

docker ps -a --filter status=exited --format '{{.Names}}  {{.Status}}'

Known cause: a Docker bridge inside 192.168.x

On 26 October 2026 Docker ran out of its default address range and put a bridge inside 192.168.0.0/20. The server then sent replies for the House VLAN into that bridge, and the house lost DNS. The server was running but unreachable from the House VLAN. The pool is now set in /etc/docker/daemon.json, so it should not recur. To check for it:

docker network inspect $(docker network ls -q) --format '{{.Name}} {{range .IPAM.Config}}{{.Subnet}}{{end}}' | grep 192.168

Expect one line only, altwfc-mystery-gift_lan on 192.168.20.0/24. That one is intentional. If any other network shows, go to that project's folder under ~/homelab and run these two commands.

docker compose down
docker compose up -d

If DNS is dead everywhere

If both AdGuards fail, the fastest way to get the house online is to blank the DHCP DNS on the router. In the ER605 at 192.168.0.1, go to Network, then LAN, edit House, and clear Primary and Secondary DNS. A blank field saves fine. Then renew the lease on each device. On the PC:

ipconfig /renew

To fix only the PC, in a Command Prompt run as administrator, set a fixed resolver:

netsh interface ip set dns "Ethernet 3" static 1.1.1.1

And put it back to automatic afterwards:

netsh interface ip set dns "Ethernet 3" dhcp

When the server is healthy again, set the House DHCP DNS back to 192.168.20.100 as primary and 192.168.40.100 as secondary.

After a power cut

The server should power on by itself and every container should start with no login. The login prompt on the console is normal and can be ignored. Give it three minutes, then check:

docker ps --format '{{.Names}}  {{.Status}}'

If the server has no network after boot, the router or access point was probably still starting. Reboot the server once they are up.

sudo systemctl reboot

Where the backups are

  • On the server: ~/backups/lab, one archive each night at 03:30, last 14 kept
  • On the PC: the labbackups folder in your user profile, pulled at 09:00 and at logon
  • On GitHub: the private repo homelab-config, with compose files, scripts and the Caddyfile, synced at 04:00

The archive includes consistent snapshots of the Vaultwarden and quiz databases. To see what an archive holds, run this on the server:

tar -tzf "$(ls -t ~/backups/lab/*.tar.gz | head -1)" | head -40

Not in git, so recreate them by hand if the server is rebuilt: the two ntfy topic files in the home folder (re-add the topic names from your phone's ntfy subscriptions), and the Diun settings file in ~/homelab/diun. The app data folders are in the nightly archive, not in git.
